# erlen-setup（初回セットアップ）

このスキルは **`SETUP.md` を実行するための進行係**です。手順の正本は `SETUP.md` であり、
このファイルはその読み方・止まりどころ・報告の型だけを定めます。

## 起動したら最初にやること（省略禁止）

1. リポジトリ直下の **`SETUP.md` を全文読む**
2. リポジトリ直下の **`AI_CONSTITUTION.md` を全文読む**（掟。特に第一条・第三条・第五条）
3. 現状を把握する: `npm run doctor` を実行し、`wrangler.jsonc` の★の埋まり具合を確認する
   （すでに構築済みかもしれない。緑ならセットアップ済みなので、勝手にやり直さず本人に確認する）
4. 利用者へ、これから行う工程と**あなたに回ってくる3つのこと**（ログイン・承認・秘密値の貼り付け）を
   短く伝えてから着手する

## 進め方の原則

- **コマンドはすべてあなたが実行する。** 利用者にターミナルを打たせない
- **1工程ずつ報告する。** 「いま何をしたか」「次に利用者がすることは何か」だけを短く
- **推測で先へ進まない。** 判断に迷ったら止まって聞く
- **秘密値をチャット・ファイル・ログに書かない**（AI_CONSTITUTION 第三条）
- **テストと検査の赤を残したまま「完了」と言わない**

## 必ず停止して人に依頼する箇所（5つ）

ここに来たら、作業を止めて依頼し、**完了の返事を待つ**。勝手に別の手段を試さない。

| # | 場面 | 依頼すること | SETUP.md |
|---|---|---|---|
| 1 | `wrangler login` の直後 | ブラウザに出たCloudflareの許可画面で「Allow」を押してもらう | §2 |
| 2 | R2バケット作成でR2の有効化を求められたとき | **課金に関わりうるので内容を説明**し、有効化の承認をもらう（無料枠内なら課金は発生しない旨も伝える） | §4 |
| 3 | Google Cloud Console を開いたとき | Googleへのログイン（2段階認証まで）。パスワード・確認コードには触れない | §7 |
| 4 | OAuth同意画面のテストユーザー登録 | ログインに使うメールアドレスを聞く。研究室メンバーを招待予定なら、その分も先に聞く | §7 |
| 5 | `wrangler secret put GOOGLE_CLIENT_SECRET` | 入力欄へ**本人に直接貼ってもらう**。値を読み上げさせない・チャットに出させない | §8 |

`SESSION_SECRET` はあなたが生成してよい（32文字以上のランダム値）。
`GOOGLE_CLIENT_ID` はブラウザ操作で取得できるならあなたが入れてよい。

## 実行順（SETUP.mdの章に対応）

飛ばさない。前の章が終わってから次へ進む。

1. **§1 前提** — `node -v`（22.5以上）→ `npm ci` → `npm test` 全緑 → `npm run doctor`
   （この時点の doctor は★未置換で赤が出るのが正常。利用者に「正常です」と伝える）
2. **§2 ログイン** — `wrangler login` →【停止1】→ `wrangler whoami` で確認
3. **§3 D1** — `wrangler d1 create erlen` → 出力の `database_id` を `wrangler.jsonc` へ書き込む
4. **§4 R2** — `wrangler r2 bucket create erlen-attachments`（必要なら【停止2】）
5. **§5 migrations** — `wrangler d1 migrations apply erlen --remote`（`--remote` を忘れない）
6. **§6 URL確定** — `wrangler whoami` / `wrangler deploy` で本番URLを確定させる
   （この時点では `/auth/login` が503なのは正常）
7. **§7 Google OAuth** —【停止3】【停止4】。ブラウザ操作で代行する。
   リダイレクトURIは `<BASE_URL>/auth/callback` の**完全一致**
8. **§8 secrets** — 3本を投入（【停止5】）
9. **§9 ★埋め** — `BASE_URL`（末尾スラッシュなし）と `OWNER_EMAIL` を `wrangler.jsonc` へ
10. **§10 deploy** — `wrangler deploy`。出力URLが `BASE_URL` と一致することを確認
11. **§11 検査** — `npm run doctor:remote` が**全項目 ✓**。赤があれば直して再実行
12. **§12 動作確認** — 利用者にブラウザで開いてもらい、ログイン → ノート作成 → 構造式 →
    反応計算 → 添付 → 検索 → 印刷レポート → **プリセット読み込み**まで一緒に確認する
13. **§13 メンバー招待**（希望があれば）— 招待メールは飛ばないこと、
    相手のメールもGoogleのテストユーザーに要ることを必ず伝える
14. **§14 バックアップ** — `erlen-backup` スキルを1回走らせ、**空のうちに手順が動くことを確かめる**

## つまずいたときの当たり方

`SETUP.md` の各章末に「つまずいたら」がある。**まずそこを読む。**
よくある3つ（読む前に思い出す用）:

- `redirect_uri_mismatch` → §7。URIの完全一致を1文字ずつ確認する
- `?login=denied` → §9。`OWNER_EMAIL` とログインしたアドレスの不一致
- ログインボタンで503 → §8。secretが揃っていない

自力で3回試して直らないことは、**推測で設定を書き換えず**、
分かっていること・試したこと・エラー文をそのまま利用者に報告して判断を仰ぐ。

## 完了報告に必ず含めるもの

- ノートのURL（`BASE_URL`）と、ログインできるメールアドレス（オーナー）
- `npm test` の結果と `npm run doctor:remote` の全項目
- 作ったCloudflareリソース（D1データベース名・R2バケット名・Worker名）
- **バックアップの取り方**（`erlen-backup` スキルの呼び方）と、定期実行のすすめ
- まだやっていない任意の作業（メンバー招待・独自ドメインなど）
